# Run ATF Generation asynchronously

This decision remains the stable asynchronous boundary for Schema Version 1. Schema Version 2 reuses the fast UI Action, exact Specification binding, UTC run stamp, and background-worker shape, but ADR-0077 supersedes the version-1-only allowance for best-effort partial artifacts: version 2 performs Runtime Business Logic Interpretation and complete Generation Plan derivation in the worker and must persist its ATF graph atomically or leave zero run-owned artifacts.

The **Create ATF** UI Action will perform its Published-Specification preflight and enqueue a background Generation Run instead of inserting the Test Suite, Tests, steps, and memberships in the form request. A background event handler or job will create those artifacts, so the Catalog Item form returns promptly at the accepted cost of eventual consistency, queue payload design, completion visibility, and background error handling that a synchronous POC would not require. This worker generates ATF metadata only; it does not execute the generated tests.

The UI Action binds the queued run to the exact Catalog Item and Current Published Specification `sys_id` resolved at click time, together with one UTC run stamp. The worker consumes those immutable inputs and does not resolve the Current Specification again; publication of a newer revision after enqueue affects only later clicks. This makes queue delay unable to change which Design a run generates from, even if the bound revision is no longer current when the worker executes.

The background worker runs in System context and retains the initiating Test Designer only as audit data; it does not reconstruct the requester's session or impersonate either Representative Test User. Authority to enqueue a run is enforced by the server-side UI Action, while the System worker is limited by implementation to reading the bound Catalog Item and Specification and creating the fixed ATF artifacts. It does not modify source design records or execute the generated tests.

For the POC, both UI Action visibility and server-side enqueue authorization require the single out-of-box `atf_test_admin` role. The demo does not authorize `atf_test_designer`, create a scoped application role, or add role inheritance; this deliberately restricts generation to ATF administrators in exchange for the smallest authorization model.

The POC has no persistent Generation Run record, status state machine, polling page, retry action, or completion notification. After enqueue, the UI Action reports only that the run was queued and displays its UTC run stamp. The System worker writes start, created-record, completion, and failure messages with the same stamp; administrators find completed artifacts by their stamped names or diagnose failures in application logs.

Background generation is best-effort and append-only rather than atomic. If an insert fails after earlier artifacts were created, the worker does not roll back, compensate, delete, mark records failed, resume, or retry; it logs the error and every `sys_id` created under the run stamp. Partial artifacts are an accepted POC outcome that an `atf_test_admin` may inspect and remove manually before starting another independent run.

After all preflights succeed, the worker creates the Test Suite first and then completes one Test at a time, Accessible before Inaccessible. For each Test it inserts the Test record, both ordered steps and their input values, and only then creates that Test's suite membership. A membership therefore means that the generated Test was fully assembled; an insert failure may leave an incomplete Test outside the Suite, but the Suite does not intentionally contain a Test whose required steps were not completed.

The asynchronous transport is one scoped Application Event enqueued by the UI Action and handled by a System-context Script Action. The Catalog Item is supplied as event record context, while the bound Specification and run stamp are transported as event parameters; requester identity is audit-only. The Script Action is a thin adapter that delegates artifact creation to one application service rather than owning generation logic. The POC does not create per-click scheduled jobs, Flow executions, or a persistent queue table.

The event uses a fixed native mapping with no JSON or delimiter payload: the record context is the Catalog Item Under Test, `parm1` is the exact bound Specification `sys_id`, and `parm2` is the UTC run stamp. The worker reads the Test Designer's audit username from `event.sys_created_by` and reads display metadata and permission inputs from the bound Specification record; it does not transmit a requester `sys_id`, snapshot the Specification fields into the event, or resolve the Current Specification again. A missing bound record stops the worker before artifact creation and is logged under the run stamp.

The version-1 worker repeats the strict compatibility guard against the bound record and proceeds only when `Schema Version = 1`. The schema-directed entry point may dispatch a separate version-2 worker only for `Schema Version = 2`; neither worker substitutes a newer Specification when the bound version is missing or unsupported.

The UI Action uses outcome-specific Platform UI messages rather than a generic failure or technical identifier dump. Preflight failures are shown with `gs.addErrorMessage()` and identify the human-readable Catalog Item, Specification number where available, Published-record count, or unsupported/blank Schema Version together with the required correction; they do not expose record `sys_id` values. Successful enqueue uses `gs.addInfoMessage()` with `ATF Generation was queued.` and the UTC run stamp. A direct unauthorized invocation reports that `atf_test_admin` is required. Technical identifiers remain in stamped worker logs, not in form messages.

On worker failure, the POC logs a concise stamped error containing the current generation stage and error summary, followed by the `sys_id` of every artifact already created under that run stamp. It does not log a full JavaScript stack trace, snapshot the Specification fields, or create a persistent error record. Stage-oriented summaries and created-record identifiers are the complete background diagnostic contract for manual investigation and cleanup.

After successful enqueue, the server-side UI Action redirects back to the same `sc_cat_item` form and displays the queued message and run stamp there. It does not navigate to an ATF Suite list, a generated artifact, or System Logs because asynchronous artifacts and stamped log entries may not yet exist. Remaining on the Catalog Item form preserves the initiating context without adding polling or refresh behavior.

The demo deployment must manually verify that `com.glide.automated_testing_impl.service_catalog_portal` is active. The application declares no hard plugin dependency and performs no separate plugin-state query; missing OOB Portal ATF metadata is reported by the worker's existing exact-cardinality preflight before artifact creation.
