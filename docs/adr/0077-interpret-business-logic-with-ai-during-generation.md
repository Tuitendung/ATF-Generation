# Interpret Business Logic with AI during generation

Version 2 uses Runtime Business Logic Interpretation after `Create ATF` binds the exact Current Specification and queues Background Behavior Generation. Published Business Logic remains the sole expected-behavior source; AI interprets that source and never reads UI Policies, Catalog Client Scripts, Script Includes, other implementation code, observed runtime branches, or Variable Test Data to determine an expectation. This supersedes ADR-0015 and ADR-0070 and the portions of ADR-0002 and ADR-0031 that excluded AI from generation, accepting a runtime model dependency in exchange for simpler Test Designer authoring.

The Test Designer authors a sequence of non-nested Guided Business Logic Behavior Blocks. Every block contains the exact structural anchors `BEHAVIOR_ID`, `TARGET`, `TRIGGER`, `LOGIC`, and `END`, and every unconditional or conditional branch contains a Test Designer-authored `OUTCOME_ID`. Variable references use Variable Design `entry_key` values, fixed choices use internal values, and display labels are invalid even when an unambiguous technical-name suggestion is available. Instructions are English-only in the POC; explicitly quoted message and scalar literals may contain any Unicode language and must be preserved exactly without translation, correction, or whitespace rewriting.

Each Behavior Block is one independent Catalog Behavioral Contract with exactly one target and one Declared Trigger: form load or one variable-specific change. A block cannot list multiple triggers; equivalent behavior for another event requires a distinct block and `BEHAVIOR_ID`. Different target blocks are never grouped or merged. Conditional logic uses one `If`, zero or more ordered `Else if` branches, and exactly one terminal `Otherwise`; nested branches are invalid, every branch declares the same target effect-property set, and neither AI nor deterministic code invents a missing branch, effect, directive, or value. The closed POC effects are `VALUE`, `VISIBLE`, `MANDATORY`, `READ_ONLY`, and at most one typed `MESSAGE` per block.

The application defines exactly two narrow Now Assist Skills and no Now Assist Agent: `Extract Catalog Behavioral Contract` and `Independently Interpret Catalog Behavioral Contract`. For each deterministically delimited block, both Skills receive the same original complete Variable Design, original block with physical-line identity, supported capability catalog, and normalized output-schema contract. The independent Skill never receives the Extractor output. Each Skill must return a complete structured contract rather than a confidence score or pass/fail opinion.

Deterministic application code canonicalizes both structured contracts and requires Canonical Interpretation Agreement across Behavior and Outcome identities, target, trigger type and variable, branch order, typed condition tree, technical identifiers, internal values, effect-property set, effect values, message scope/type/text, exact literals, and source-line mappings. Raw JSON property order is irrelevant, but every semantic difference is blocking; code does not prove two different boolean trees equivalent, select one interpretation, or ask a third pass to vote.

Interpretation is Block-Scoped. Deterministic code owns anchor parsing, block splitting, retry counting, schema enforcement, canonical comparison, cross-Design and global validation, ownership and cycle checks, Variable Test Data selection, Coverage Assignment Search, Change Stimulus planning, immutable Generation Plan creation, adapter selection, and atomic ATF persistence. AI owns only the conversion of one complete Guided Business Logic block into the normalized contract and cannot repair Design, invent Test Data, infer grouping, create ATF steps, or persist artifacts.

Canonical semantic disagreement is non-retriable. It records `AI_INTERPRETATION_INCONSISTENT`, includes structured non-raw differences and source evidence, and creates zero ATF artifacts. The application does not retry until two answers match, choose one answer, use majority voting, or silently fall back. A technical failure—timeout, transport failure, service unavailability, rate limit, malformed or truncated response, or response-schema failure—receives exactly one retry with the same runtime model deployment, prompt version, original Design, output schema, and generation settings. If the identical retry fails, the run records `AI_INTERPRETATION_TECHNICAL_FAILURE`, creates zero artifacts, and does not classify the Current Specification as invalid. An agreed contract that is ambiguous, unsupported, incomplete, invalid, uncovered, or inconsistent with other Design Sections produces `DESIGN_INVALID` and zero artifacts.

Only after every block agrees does deterministic code merge the contracts, perform Atomic Design Validation, select Design-owned Test Data, derive one Test per Declared Outcome of each single-trigger block, and construct the complete Generation Plan. AI never receives Variable Test Data and never invents a Candidate value. No ATF insert occurs before the complete plan passes, and persistence must create the complete behavior graph atomically or leave zero run-owned artifacts.

Version-2 interpretation and generation execute in the background. The UI Action performs only fast authorization, exact Current Specification and Schema Version binding, required-field and structural-anchor preflight, UTC run-stamp creation, and queueing. The bound worker rechecks the immutable identity and performs every AI, validation, derivation, and persistence step. Successful provenance is stored in generated Suite and Test descriptions; failed runs are diagnosed only through the existing run-stamped system-log seam. The POC creates no notification, Execution Tracker integration, custom run table, or mutable execution-state field on a Published Specification.

AI Interpretation Evidence contains only non-raw provenance: run and Specification identity, Behavior and Outcome IDs, source locations, prompt and output-schema versions, input and canonical-contract hashes, attempt counts, agreement state, structured differences, and model metadata only when exposed. Raw prompts, raw responses, duplicate Variable Design, duplicate Business Logic, and complete model conversations are not persisted, and no custom Prompt, Response, Interpretation, or Generation Run table is created.

The POC uses the Now Assist model active for the configured capability at runtime and does not pin, qualify, or compatibility-gate model deployment or version. Missing model metadata does not block generation, and equality across separate runs of unchanged Design is neither guaranteed nor tested. Canonical Interpretation Agreement within every individual run remains mandatory.

All AI-dependent production work is blocked by the Runtime AI Feasibility Gate on the configured target ServiceNow release. A throwaway background harness must invoke two separate throwaway Skills without sharing outputs, enforce structured results, compare both contracts to each other and reviewed expected contracts, preserve exact Unicode and prompt-like quoted literals, exercise technical retry and semantic non-retry, record only non-raw evidence, and create zero ATF artifacts. Every supported fixture must return the exact expected canonical contract through ten repeated runs, and every invalid or ambiguous fixture must be rejected every time. A failed gate blocks Runtime Business Logic Interpretation and the complete v2 AI generation path pending an explicit scope decision; it never authorizes a deterministic DSL parser, one-pass AI, a Now Assist Agent, direct AI artifact generation, or partial generation.
